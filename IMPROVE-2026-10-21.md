## Top recommendations (ranked, with effort S/M/L)

1. **NIP-66 2026 tag-taxonomy alignment (M).** The app already consumes kind-30166 from multiple monitors (relay.nostr.watch, relaypag.es, monitorlizard.nostr1.com) and kind-10166 announcements — good foundation. The 2026 monitor ecosystem (e.g. BigBrotr 5.10, Mar 2026) now emits richer 30166 tag sets: NIP-11 `attributes` surfaced as `W` tags, plus dns/http/requirement/type tags, and NIP-32 geo (`ISO-3166-1`, `nip66.label.city`, `IANA-tz`) and network (`IANA-asn`, `IANA-asnOrg`) labels. Parse these to upgrade the auto-tagger (real geohash/city and ASN instead of inference) and to detect requirement tags (auth/payment) directly rather than from NIP-11 fetches. Note: I could **not** verify a specific "relay-roles event (Jun 2026)" change this session — NIP-43 roles (kind 33534/13534) are already consumed per NIP.md, which appears to be the current roles mechanism; re-check nostr-protocol/nips before scheduling work.
2. **Dependency refresh (M).** This is the org's oldest mkstack snapshot: nostr-tools **^2.13.0 → 2.25.2** (12 minor lines behind; NIP-17/44/59 handling and relay pool fixes), react-router-dom ^6 → ^7, tailwindcss ^3 → ^4 (+ `tailwindcss-animate` → `tw-animate-css`), recharts ^2 → ^3, `@nostrify/nostrify` ^0.51.0 → ^0.55.1 (match 0xsigner; converge the org on one Nostr stack). **`@getalby/sdk` ^5.1.1 appears unmaintained** (registry metadata shows last release >2 years ago) — if it's only used for NWC wallet connect, evaluate the lighter `@getalby/lightning-tools` (9.0.1 current) or nostr-core; if unused, delete it (it's the heaviest dep tree in the app).
3. **Install the crawler workflow (S).** `scripts/crawl.github-workflow.yml` sits uninstalled in `scripts/` — move it to `.github/workflows/` so the crawl actually runs on schedule; without it the directory's freshness claims decay silently. Also wire `verifier/v1/run.sh` + `logic.test.ts` into CI (the NIP-67 EOSE-hint and NIP-77 NEG-OPEN probes are exactly the kind of check that rots without a gate).

## Quick wins (code/config)

- NIP.md documents kind-30078 submissions carrying an `encrypted_notes` NIP-44 tag to the app owner — good; add a client-side test proving the note decrypts only with the owner key.
- WoT weighting (5x/3x/2x/1x) is fully specified in NIP.md — the kind-3 crawl is expensive in-browser; cache the WoT graph in idb with TTL and recompute in a Web Worker.
- The auto-tagger maps NIP-50 → "High Performance" — that's wrong semantically (NIP-50 = search capability); use a "Search" tag. NIP-42 → "Paid Access" is also off (auth ≠ paid); use "Auth Required".
- `limit`/paging on relay directory queries: use NIP-01 until/since windows against kind-30078 rather than re-fetching full sets.
